## What failed before the fix

Play Mode left `DelegationBridge.Orchestrator.ScenarioPolicy` null because the editor process directory is the Unity install, so the default `data/scenarios` walk never ran (`loadedFrom` empty). Unit detail therefore showed `DOCTRINE: —`. After the policy loaded, opposing units still showed `WeaponsFree` because the detail projection always resolved doctrine as friendly.

## Code changes

- `ScenarioPolicyPlayModeLoad.EnsureLoadedFrom` loads `data/scenarios` from a start path. `DelegationBridgeHost.Awake` calls it with `Application.dataPath` before the bridge is constructed.
- `UnitDetailBridge` sets the doctrine line from the unit's already-bound effective policy, so hostile-1 shows `WeaponsTight`.
- Tests: `EnsureLoadedFrom_unity_assets_path_binds_classify_side_roe`, `Classify_detail_shows_friendly_free_and_opposing_tight`.
- `DelegationBridge.cs` was not edited. Replay hash `17144800277401907079` is still present under `tests/` and `data/`.

Plugin DLLs under `unity/ProjectAegis/Assets/Plugins/ProjectAegis` were republished so the open editor could load the new type. Those binaries stay gitignored.
