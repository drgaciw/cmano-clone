5. Scenario data (JSON)

Scenarios are documents, not SQLite rows. They reference catalog snapshot / platform ids.

KindPath patternContents
Scenario document *.scenario.json, examples under data/scenarios/examples/ Metadata (dbRef, seed, policyId), ORBAT, missions, RPs
Scenario policy data/scenarios/*.policy.json Detection, ROE, timelines, combat-domain hooks
Validation goldens assets/data/scenarios/validation/, data/scenarios/validation/ CI / regression packages

Map authoring place path: UI form → MapAuthoringSurface → Bus.PlaceUnit / UpsertUnit → scenario JSON ORBAT (string PlatformId).

7. Write model

  1. Propose into catalog_staging_* (+ batch).
  2. Validate / review (TRL, quarantine, gates).
  3. Promote to live tables with catalog_change_log audit.
  4. Optional snapshot / db_release bind for scenario compatibility.

CLI: Mission Editor catalog commands · CMO markdown import · OSINT pipelines.

8. Quick commands

# Platform domains
sqlite3 assets/data/catalog/baltic_patrol.db \
  "SELECT domain, COUNT(*) FROM platform GROUP BY domain;"

# Sample platforms
sqlite3 -header -column assets/data/catalog/baltic_patrol.db \
  "SELECT platform_id, display_name, domain, nationality FROM platform LIMIT 20;"

# C# resolve
var reader = CatalogReaderFactory.ResolveForScenario("baltic-patrol");
